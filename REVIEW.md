# REVIEW.md

Part A review of the starter `app/main.py`.

| # | Where (function / area) | What is wrong | How to notice (test / input / symptom) | Fix applied |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses `datetime.combine(punch_in.date(), ...)` for shift start without accounting for overnight shifts (`shift_end <= shift_start`). | For employee on `22:00–06:00` shift punching in at `04:00:00 IST` on `2026-07-07`, starter compares against `2026-07-07 22:00` (in future, elapsed is negative, returns 0 late minutes). Expected: belongs to `2026-07-06` shift starting at `2026-07-06 22:00`, giving 360 late minutes. | In `_shift_start_for_punch` and `punch_in`, if `shift_end <= shift_start` and punch-in time is `< shift_end`, shift start date is shifted back by 1 day (`attendance_day - timedelta(days=1)`). |
| 2 | `compute_late_minutes` | Assumes naive/local host datetimes and does not enforce whole-second truncation before calculations per R1. | Input `punch_in = 09:40:00.900` for `09:30` shift. Starter computes elapsed as `600.9s > 600s`, returning 10 late minutes. Expected per R1: `09:40:00.900` truncates to `09:40:00`, elapsed is 600s, returning 0 late minutes. | Explicitly convert to IST and truncate microseconds (`_truncate_seconds()`) before elapsed second and minute calculations. |
| 3 | `compute_work_hours` | Python built-in `round()` uses round-half-to-even (banker's rounding) rather than decimal half-up rounding (R4). | Duration of 54 seconds = `0.015 hours`. Python `round(54 / 3600, 2)` incorrectly rounds down to `0.01`. Expected per R4: `0.02` hours. | Use `decimal.Decimal` with `ROUND_HALF_UP` to round `(punch_out - punch_in).total_seconds() / 3600` to 2 decimal places. |
| 4 | `compute_overtime` | Does not enforce the 30-minute minimum overtime threshold (R3). | Punch out 29 minutes after shift end (e.g., `18:59:00` for `18:30` shift end). Starter returns `29`. Expected: `0` (overtime only counts when >= 30 minutes). | Return `whole_minutes if whole_minutes >= 30 else 0`. |
| 5 | `compute_overtime` | Constructs shift end on the same calendar day even for overnight shifts. | For a `22:00–06:00` shift on date `2026-07-06`, punch out at `06:40:00` on `2026-07-07`. Starter compares against `2026-07-06 06:00` (24h earlier), yielding 1480 overtime minutes instead of 40 minutes. | Take `shift_start`; when `shift_end <= shift_start`, advance shift end by 1 day (`attendance_day + timedelta(days=1)`). |
| 6 | Mongo configuration | Starter silently fell back to local defaults (`mongodb://localhost:27017` / `attendance_db`) instead of making environment configuration explicit. | Unset `MONGO_URI` or `MONGO_DB`; the application silently connected to an unintended default local database. | Require explicit configuration via `os.getenv("MONGO_URI")` and `os.getenv("MONGO_DB")`, returning 503 if unconfigured. |
| 7 | `health` | Returns HTTP 200 without checking MongoDB connectivity. | Stop MongoDB and call `GET /health`; starter still reported `{"status": "ok"}`. Expected: HTTP 503 when database is unreachable. | Execute `db.command("ping")`; if ping fails or database is unconfigured, return HTTP 503. |
| 8 | `create_employee` | Application-level `find_one` duplicate check followed by `insert_one` is race-prone; no database uniqueness guarantee existed. | Send concurrent requests with the same `emp_code`; both pass `find_one` and insert duplicate employees. | Create a unique index on `emp_code` at startup and map PyMongo `DuplicateKeyError` to HTTP 409. |
| 9 | `create_employee` | Does not validate that shift times are valid `HH:MM` formats or that `shift_start != shift_end`. | Submit `shift_start="25:90"` or identical start/end values (`"09:30"` and `"09:30"`). Starter accepted them. Expected: HTTP 422. | Validate 24-hour `HH:MM` format and enforce `shift_start != shift_end` via Pydantic model validator. |
| 10 | `create_employee` | Stored `created_at` as a naive local host datetime and returned internal MongoDB `_id` and BSON datetime in response. | Create employee and inspect response; `_id` is exposed and `created_at` is an ISO datetime string varying by server timezone. | Store UTC instant in MongoDB, omit `_id` from response, and serialize `created_at` as integer epoch milliseconds. |
| 11 | `list_employees` | `skip = page * page_size` skips the first page of results entirely. | Request `GET /employees?page=1&page_size=20`; starter skips 20 records (offset 20 instead of 0), returning page 2. | Use `skip = (page - 1) * page_size`. |
| 12 | `list_employees` | `total` counted all documents in the collection rather than the department-filtered result set. | Filter `GET /employees?department=QA` where QA has 1 employee out of 8 total. Starter returned `total: 8`. Expected: `total: 1`. | Pass the filter query `q = {"department": department}` into `db.employees.count_documents(q)`. |
| 13 | `list_employees` | Does not sort by `emp_code` ascending and does not validate pagination query bounds. | Records returned in arbitrary database insertion order; `page=0` or `page_size=500` accepted. Expected: sorted by `emp_code` ASC; bounds rejected with 422. | Sort by `emp_code` ascending; constrain `page = Query(default=1, ge=1)` and `page_size = Query(default=20, ge=1, le=100)`. |
| 14 | `punch_in` | Does not verify employee existence before accessing `emp["shift_start"]`. | Punch in with unknown `emp_code="UNKNOWN"`. Starter crashed with unhandled `TypeError` (HTTP 500). Expected: HTTP 404. | Check employee existence via `find_one` and return HTTP 404 if not found. |
| 15 | `punch_in` | `if body.punched_at:` treated `0` as falsy (defaulting to current time), and accepted seconds-looking timestamps. | Send `punched_at=0` or seconds `1718000000`. Starter silently substituted current time or year 1970. Expected: HTTP 422. | Check `punched_at is not None` and enforce `100000000000 <= punched_at <= 4102444800000` (rejecting seconds with 422). |
| 16 | `punch_in` | Used host-local `datetime.fromtimestamp()` and did not truncate instants to whole seconds (R1). | Send a timestamp around midnight IST with fractional milliseconds; host timezone altered attendance date and milliseconds leaked into calculations. | Convert epoch ms via UTC to IST, truncate to whole seconds (`sec = value // 1000`), and store UTC naive datetime in MongoDB. |
| 17 | `punch_in` | Did not restrict `status` to allowed presence statuses (`PRESENT`, `WFH`, `ON_DUTY`). | Submit `status="LEAVE"` or `status="ABSENT"`. Starter accepted it and created an attendance record. Expected: HTTP 422. | Constrain request status with `PresenceStatus = Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 18 | `punch_in` | Application-level duplicate check followed by insert is race-prone under concurrency. | Send concurrent identical punch-ins for the same employee and date; both can pass check and insert duplicate logs. | Create a compound unique index on `(emp_code, date)` and map PyMongo `DuplicateKeyError` to HTTP 409. |
| 19 | `punch_in` | Response included MongoDB `_id` and raw BSON datetimes instead of the contract `AttendanceRecord` schema. | Compare response against `AttendanceRecord` in `openapi.yaml`; `_id` was exposed and punch timestamps were not epoch ms. | Strip `_id` and serialize `punch_in` and `punch_out` as integer epoch milliseconds. |
| 20 | `list_attendance` | Loaded all matching documents into a Python list (`list(db.attendance_logs.find(q))`), then sorted and sliced in memory. | Test on large collections (~100,000 records); causes high latency and severe memory bloat. | Apply count query separately and delegate sort, skip, and limit directly to MongoDB (`.sort(...).skip(skip).limit(page_size)`). |
| 21 | `list_attendance` | Sorted only by `date` descending, omitting the required `emp_code` ascending tie-breaker. | Query multiple records sharing the same date; employee ordering on that date was non-deterministic. | Sort by `[("date", DESCENDING), ("emp_code", ASCENDING)]`. |
| 22 | `list_attendance` | Did not validate date strings or reject reversed date ranges (`date_from > date_to`). | Call `GET /attendance?date_from=2026-10-20&date_to=2026-10-01` or `date_from=invalid`. Starter executed query with empty results. Expected: HTTP 422. | Validate `YYYY-MM-DD` calendar dates and return HTTP 422 if invalid or if `date_from > date_to`. |
| 23 | `list_attendance` | Did not validate pagination query bounds. | Call `GET /attendance?page=0` or `page_size=200`. Starter accepted invalid pagination bounds. Expected: HTTP 422. | Constrain `page = Query(default=1, ge=1)` and `page_size = Query(default=20, ge=1, le=100)`. |

## Checked and not considered a defect

- The default page size of 20 is correct under R10; the defect was the skip formula and missing bounds validation.
- `date_from` and `date_to` are intended to be inclusive; the starter's `$gte` and `$lte` operators match that requirement.
- `work_hours` should remain `null` until punch-out, and the starter's initial `None` value is correct.
- `overtime_minutes` should start at `0`, `half_day` at `false`, and `history` at an empty array for a new punch-in; those initial values are correct.
